PROMPT BASE PARA GERAÇÃO DO HTML UNIFICADO

Você está unificando 3 players KODUX em um único HTML base.

Estrutura de divs (APENAS layout, sem reescrever JS/CSS):

1. div#arch-hud — topo fixo, contém .logo-orb + .title-block + .symbol-bar + .engine-row
2. div#yt-universal-player — iframe viewer YT com .yt-url-bar + iframe#ytEmbed + .yt-controls
3. div#nebula-block — Nebula Pro TTS/PDF com .nebula-header + #items + .player.inline-docked
4. div#output-area — Motor output: #outputContainer com .response-block x N
5. div#narrative-dock — bottom fixed: voice-viz + now-playing + ⏮⏸⏭

Cada zona se comunica via window.postMessage({type:'voice-trace', text, arch, engine}).
O YT player é apenas um iframe com src dinâmico. NÃO reescreva o JS existente.

REVIEW — O QUE FAZER PARA FUNCIONAR

  • Criar wrapper div#unified-player-shell como raiz única, substituindo os três body's separados
  • Mover os <style> de cada arquivo para um único <head> (evitar conflito de .card, .player, .orb)
  • Prefixar classes conflitantes: .motor-card, .nebula-card, .yt-card para isolar escopos
  • O iframe YT: usar id="ytEmbed" com src="" — JS já existente no Motor-Dissolver injeta a URL via postMessage
  • Nebula Pro .player: adicionar classe .inline-docked para usar o CSS de dock já definido em #libCard
  • Adicionar MotorBridge no <script> final — escuta TTS events e dispara postMessage para YT e output
  • Namespace de IDs: motorDock (Motor), ytEmbed (YT), nbPlayer (Nebula) — sem colisão
  • CDNs necessários: Tailwind (Motor), pdfjs@3.6.172 (Nebula), JSZip, Tesseract.js — já presentes nos 3 arquivos
  • CSS safe-area (env()) do Nebula deve ser o CSS body raiz — Motor tem body padding:24px que conflita
  • O narrative dock (zona E) recebe eventos via window.addEventListener('message') — já tem listener no Motor
